# Secrets used by the manifests

No Secret is committed and none is rendered by kustomize. They are created once per environment
from files generated by `scripts/generate_credentials.py` (which also writes the exact
`oc create secret` commands). `secret-templates.yaml` shows the shape with placeholders only.

Every Secret is mounted as files (mode 0440) under `/var/run/secrets/nvb/...`; applications read
the `*_FILE` settings. The only exceptions are the disposable test PostgreSQL / test core, whose
upstream images take their own passwords from environment variables.

| Secret | Keys | Mounted by | Content |
| --- | --- | --- | --- |
| `core-adapter-core-token` | `token` | core-adapter | RAW token the adapter presents to the core (`ADAPTER_CORE_TOKEN_FILE`) |
| `core-adapter-clients` | `clients.json` | core-adapter | SHA-256 digests + scopes of the adapter's callers (`ADAPTER_CLIENTS_FILE`) |
| `adapter-token-statements-api` | `token` | statements-api | RAW token, scopes `identity:resolve accounts:read discovery:read` |
| `adapter-token-statements-worker` | `token` | statements-worker | RAW token, scope `statements:read` |
| `adapter-token-statements-batch` | `token` | statements batch CronJob | RAW token, scope `discovery:read` |
| `adapter-token-loans-api` | `token` | loans-api | RAW token, scopes `identity:resolve accounts:read` |
| `adapter-token-loans-worker` | `token` | loans-worker | RAW token, scope `summaries:read` (manifests only, no entries) |
| `statements-db-app` | `password` | statements api/relay/worker/ops | least-privilege runtime role `nvb_statements_app` |
| `statements-db-owner` | `password` | statements migration Job only | schema owner `nvb_statements_owner` (DDL) |
| `loans-db-app` | `password` | loans api/relay/worker/ops | least-privilege runtime role `nvb_loans_app` |
| `loans-db-owner` | `password` | loans migration Job only | schema owner `nvb_loans_owner` (DDL) |
| `statements-broker` | `username`, `password` | statements relay/worker | RabbitMQ user limited to `nvb.statements.*` |
| `loans-broker` | `username`, `password` | loans relay/worker | RabbitMQ user limited to `nvb.loans.*` |
| `statements-s3` | `access-key`, `secret-key` | statements api/worker | key scoped to the private bucket |
| `keda-rabbitmq` | `host` | KEDA TriggerAuthentication (optional) | `amqp(s)://nvb_monitor:...@host/nvb`, monitoring-only user |
| `core-integration-clients` | `clients.json` | test core only | digests + scopes of the CORE's integration clients (`NVB_INTEGRATION_CLIENTS_FILE`) |
| `core-test-db` | `password` | test core + init Job | disposable core database role |
| `core-test-seed` | `NVB_SEED_*_PASSWORD` | test core seed Job | synthetic demo logins of the disposable core |
| `test-postgres-admin` | `password` | disposable PostgreSQL | its admin password |
| `test-rabbitmq-definitions` | `definitions.json` | disposable RabbitMQ | vhost, users (password HASHES), permissions |
| `test-objectstore-config` | `s3.json` | disposable object store | S3 identities |

`*-tls` Secrets (`core-adapter-tls`, `statements-api-tls`, `loans-api-tls`, `gateway-tls`,
`core-test-tls`) are issued automatically by the OpenShift service CA from the Service annotation;
do not create them.

ConfigMaps that carry CA bundles (not secret): `nvb-service-ca` (injected), `core-ca` (test:
injected; PoC: created by infra from the core load balancer's CA, key `ca.crt`), `deps-ca`
(PoC only, key `ca.crt`).

## Raw token <-> hashed client file

```
caller holds RAW token (Secret, file)        callee holds SHA-256 digest + scopes (clients.json)
-------------------------------------        ----------------------------------------------------
core-adapter-core-token/token        ---->   core:    NVB_INTEGRATION_CLIENTS_FILE  client nvb-core-adapter
adapter-token-<client>/token         ---->   adapter: ADAPTER_CLIENTS_FILE          client <client>
```

A digest list may hold two digests per client (current + next), which is how rotation works
without downtime - see docs/CONFIGURATION.md.
